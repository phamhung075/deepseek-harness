# Agent Note: Observing durable appends a Host did not write

Status: implemented

English | [中文](2026-09-13-durable-append-observation.zh.md)

## Problem

A delegated job runs in another process. It appends to the same session artifact the Web GUI reads — `${DSH_HOME}/sessions/<project>/<id>/session.jsonl.zstd` — and the GUI could neither report nor follow it. `ApiSessionList.summarizeCold` hardcoded `running: false` for every session this Host does not hold, so a running job looked idle, and `SessionHistoryController.follow` fed live frames only from the in-process `session/event` bus, whose listener never fires for another process's writes: an opened cold session froze at its opening snapshot while its writer kept working.

Nothing watched session artifacts — the tree's only file watchers observe credentials and settings files — and the persistence seam could not express the observation even in principle. `stat` returns an opaque revision, which proves that something changed without saying what arrived, and `api-session/status` was emitted only from an in-process Agent's status.

## Decision

`@deepseek-ai/dsh-session-persistence` declares a second, optional Service Definition: `SessionAppends` (`ctx.sessionAppends`), whose `watch(id)` returns an owned subscription yielding batches of the logical events that became durable after it resolved. The JSONL backend provides it beside `ctx.sessionPersistence`; `@deepseek-ai/dsh-api-session-controller` consumes it for the list's running flag and for follow. Its presence is deployment-shaped: a backend that cannot observe foreign appends does not register it, consumers read it with `ctx.get('sessionAppends')`, and the Session Controller warns once, naming the missing service, when it is absent.

A subscription reports appends, never the prefix already durable when it opened, and that is the ordering contract which makes it gap-free: a consumer opens the subscription FIRST and reads the prefix it continues from afterwards, so an event durable between the two steps arrives on the stream and the consumer's own cursor decides whether it has already consumed it. A torn record is withheld until the bytes completing it land. A backend that loses its place — a repair truncating the artifact, a file replaced under the same path, a subscription that opened inside a frame the writer later rewrote — may replay events the consumer already saw rather than leave a hole, so every consumer tolerates an event at or below its cursor. The follower's existing `item.seq < expectedSeq` skip is that tolerance; the idle observer simply re-folds.

A writer can also leave the reader behind without the reader losing its place. A turn interrupted in one process and resumed by another appends a batch that re-emits seqs the artifact already holds, so the file grows while the appended records run backwards; no truncation or replacement triggers a restart, and the appended bytes decode cleanly. The reader treats every appended seq at or below the one it reported last as already delivered: it drops those records, keeps its position, and continues from the first genuinely new seq, which keeps `poll`'s contiguous output and keeps the subscription alive for a session that is still being written. Only an appended seq AHEAD of the expected one ends the stream, because bytes the stream never saw are a hole nothing can absorb.

The JSONL provider decodes only what a writer appended. It holds the artifact's consumed byte offset, decodes the complete Zstandard frames past it through the existing frame scanner and decoder, retains an incomplete trailing frame, and for plaintext artifacts retains an incomplete trailing line; bytes are consumed whether or not they decode, so an unfinished record is re-read rather than lost. `fs.watch` on the session's directory reports appends promptly and a `watchPollIntervalMs` poll is the safety net for a platform whose watcher is silent or unavailable, so correctness does not depend on notification. Subscriptions are owned: the service keeps them in a set, `close()` releases the watcher, timer, listener, and read loop, and the provider fiber's disposer closes every live subscription and awaits its read loop, which is what the disposal tests observe.

`SessionPersistenceSnapshot` gains an optional `lastModifiedAt` in Unix epoch milliseconds, the artifact modification time the JSONL backend already had in the stat it performs for `revision`. It exists because a Host that starts while a job is mid-turn has no append to observe yet, and the newest writer's recency is the only cheap evidence that the run is live.

The Host-side observer is `ColdSessionActivity` in the Session Controller. It polls `persistence.list()` every `coldActivityPollMs`, adopts sessions whose artifact was modified within `coldActivityIdleMs` up to `coldActivityMaxSessions` at once, subscribes to their appends, folds `turn/start` and `turn/end` into an open-turn flag, and emits `api-session/status` on each transition, so the GUI's sidebar learns the change without a reload. A session is running while the last observed turn is not closed and its writes are recent; an observed `turn/end` settles it immediately, and the idle window is only the guard for a writer that died mid-turn and never wrote one. A session this Host holds in `ctx.sessions` or `ctx.agents` is never observed, and one that becomes live after being observed is released and its running status retracted, which keeps the in-process path authoritative.

`follow` opens the durable subscription before its opening observation and merges the batches into the follower's ordered buffer, so a cold session streams its appends while its snapshot stays the same durable cut. A follow that opened a durable subscription does not promote the session: promotion would attach it to this Host, after which the Session list would treat an in-process Agent that is not running as authoritative and the next follow would take the in-process bus, so opening the row once would report idle and freeze the transcript while the other process kept working. Activation stays on demand, where prompting already resolves the Agent through `resolveAgent`. The in-process bus remains authoritative for sessions this Host holds: the durable subscription is skipped outright for them, and duplicate seqs from both sources are dropped by the follower's existing seq check rather than by a new ordering rule.

## Alternatives considered

**Add an abstract `watch` to `SessionPersistence`.** It obliges every provider, and this tree has eight subclasses — the JSONL backend plus seven test doubles — fifty-one further `ctx.provide('sessionPersistence', …)` stubs, and two shared contract suites that would have to grow a capability most persistence consumers never call. An optional companion definition confines the obligation to the provider that can honor it and makes its absence explicit at the one consumer that needs it.

**Report the running flag from write recency alone.** Modification time is cheap and needs no turn state, but it cannot settle a session promptly: a run that finished would keep reporting running for the whole idle window, and the acceptance rule for this change is that a closed turn is idle. Turn boundaries give that, and recency only guards a writer that died mid-turn.

**Re-read the whole stored log on every append.** It reuses `observeSession` and needs no incremental decoder, but a running session appends several times per second, so decoding the whole log per append is quadratic in a session's length. Decoding only complete appended frames costs the appended bytes.

**Watch every stored session.** A per-session watcher for the whole corpus would find activity without polling `list()`, but a store holds hundreds of artifacts and only the recently written ones can be running. Bounded adoption of recent writers keeps the watcher count proportional to concurrent runs.

**Report foreign activity through the bridge or a side channel.** The offload bridge knows which session it started, so it could push status itself. That works only for jobs the bridge started and couples the GUI to one launcher; only the artifact is shared by every writer, including ones the GUI never sees start.

**Let a durable follow promote the session it opened.** Promoting keeps the eager warm activation a cold open had before this change, but the promotion attaches the session to the Host, which hands authority to an in-process Agent that is not running the job: the row reports idle and the next follow takes the in-process bus, so the run stops streaming while its writer keeps appending. Skipping promotion for a durable follow keeps one authoritative source and leaves activation on demand, where prompting resolves the Agent through `resolveAgent`.

## Consequences

The Web GUI reports a session another process is running as running, stops when its durable turn closes or its writes go idle, and streams that session's appends into an open transcript instead of freezing at the snapshot. Sessions the Host runs are untouched: their list rows and status pushes still come from `ctx.agents`, and follow still uses the in-process bus.

Two boundary effects remain. A cold observation's log is balanced with in-memory interrupted-turn closers, so a follower of a session whose turn is still open resumes at the balanced cursor and skips the stored events that fall at or below it — the wire stays contiguous, but the first events of the appended run may not be re-delivered. The list is still a pull on connect, so a session another process created appears in the sidebar after a reload, which the workspace-attach plugin already files under its project workspace.

The observer adds background work to the Host: one `persistence.list()` per poll interval, plus a watcher and a poll timer per adopted session. Both are bounded by configuration (`coldActivityPollMs`, `coldActivityIdleMs`, `coldActivityMaxSessions` on the Session Controller; `watchPollIntervalMs` on the JSONL backend). The Web GUI copy is unchanged — no new user-facing string was needed.

## Testing

`packages/session/session-persistence-jsonl/tests/appends.spec.ts` mounts two backends over one root, the second standing in for another process because write ownership is in-process, and pins: another writer's append arriving as the logical events a packed storage row carries, one batch per durable append, a plaintext line withheld until its final bytes land, a Zstandard frame withheld until its final bytes land, an append that re-emits seqs the stream already reported being absorbed so the next contiguous append still arrives, an append that skips a seq ending the stream, a subscription that stops reporting after `close()`, every subscription released on provider fiber teardown, a refusal for a session with no artifact, and a follower anchored past an existing prefix.

`packages/api/session-controller/tests/session-durable.host.spec.ts` composes the real Session Controller, Session store, Agent registry, and JSONL backend, and pins: a cold row reporting running while the other writer is mid-turn, the two `api-session/status` transitions (running, then settled when `turn/end` lands), a session this Host holds reporting through the in-process path instead, a follower receiving an appended turn's events in seq order, a session this Host holds not being observed durably at all, and an opened cold session staying unattached to this Host so a second follow still streams the other process's appends.
